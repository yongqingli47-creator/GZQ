# Agent Workflow Rules

When working in this repository:

1. Start with the narrowest actionable unit: a file, command, symptom, prompt, or workflow.
2. Prefer local evidence over speculation.
3. Make the smallest useful change before widening scope.
4. After a meaningful edit, run the cheapest relevant validation step.
5. Surface assumptions, blockers, and residual risks explicitly.

Use the available skills when they match the task:

- Use `research-planning` for turning a vague idea into a structured research or implementation plan.
- Use `empirical-analysis` for data, scripts, notebooks, identification, robustness, and reproducibility tasks.
- Use `manuscript-polish` for paper sections, response letters, academic framing, and language tightening.
- Use `literature-synthesis` for collecting, structuring, and comparing literature around a research question.
- Use `zotero-library-ops` for Zotero API syncing, Better BibTeX grounded reference work, and repository-based batch literature tasks.

For literature-heavy work in this repository:

1. Read repository literature sources before synthesizing or drafting.
2. Treat `literature/bib/*.bib` as the citekey and bibliography source of truth.
3. Treat `literature/metadata/zotero_items.json` and `literature/metadata/zotero_items.md` as the working snapshot for metadata and abstracts.
4. If the local library snapshot is stale or missing, refresh it before doing large-scale review, matrix, or outline work.

Preferred response traits:

- Concise by default
- Evidence-led
- Reproducibility-aware
- Clear about tradeoffs
- Suitable for doctoral supervision and revision guidance
